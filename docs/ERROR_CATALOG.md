# 사용자 오류 분류 및 표시 기준

이 문서는 Aerial Survey Manager에서 발생하는 오류를 사용자에게 안전하고
일관되게 안내하기 위한 기준입니다. 실제 예외 문자열을 화면에 전달하지 않고,
오류 코드와 사용자용 설명, 조치 방법, 오류 참조번호를 사용합니다.

## 1. 표시 형식

API와 처리 상태 응답은 최종적으로 다음 형식을 사용합니다.

```json
{
  "error": {
    "code": "EO_PARSE_FAILED",
    "message": "EO 파일 내용을 읽을 수 없습니다.",
    "action": "파일 형식과 구분자, 필수 열을 확인한 뒤 다시 시도해주세요.",
    "reference_id": "ERR-20260722-A1B2C3D4E5F6",
    "retryable": false
  }
}
```

- `code`: 프로그램과 문서에서 변하지 않는 영문 오류 코드
- `message`: 사용자에게 무엇이 실패했는지 설명하는 한두 문장
- `action`: 사용자가 바로 수행할 수 있는 조치
- `reference_id`: 운영 로그와 오류 묶음을 찾는 참조번호
- `retryable`: 같은 입력으로 즉시 다시 시도할 수 있는지 여부

참조번호는 `ERR-YYYYMMDD-<무작위 12자리>` 형식을 사용합니다. 화면, API
응답, 처리 상태 파일, 서버 로그에 같은 값을 기록합니다.

## 2. 오류 대분류

| 분류 | 코드 접두어 | 포함 범위 | 기본 담당 영역 |
|---|---|---|---|
| 인증·세션 | `AUTH_` | 로그인, 만료된 세션, 접근 불가 | API·프론트 |
| 요청·상태 | `REQUEST_`, `RESOURCE_` | 잘못된 요청, 없는 대상, 상태 충돌 | API |
| 입력 데이터 | `INPUT_`, `EO_`, `CRS_` | 이미지·EO·좌표계 검증 및 파싱 | 업로드·프로젝트 |
| 파일·경로 | `FILE_` | 파일 없음, 형식, 읽기 권한 | 업로드·스토리지 |
| 카메라 IO | `CAMERA_` | 카메라 모델, `io.csv`, 재파싱·동기화 | 카메라 관리 |
| 처리 작업 | `PROCESSING_` | 대기열 등록, 단계 실행, 체크포인트, 취소 | API·워커 |
| GPU 실행 환경 | `GPU_` | 장치, 드라이버, 런타임 연결, 메모리 | 처리 워커 |
| 저장소 | `STORAGE_` | 읽기·쓰기·용량·결과 파일 | API·워커 |
| DB·대기열 | `DATABASE_`, `QUEUE_` | DB 연결·트랜잭션, Redis·Celery | API·워커 |
| 내보내기·클립 | `EXPORT_`, `CLIP_` | 변환, 도엽 선택, 범위, 결과 생성 | 내보내기 |
| 네트워크 | `NETWORK_`, `SERVER_` | 브라우저 오프라인, 시간 초과, 서버 연결 | 프론트 |
| 내부 오류 | `INTERNAL_` | 위 분류로 확정할 수 없는 예외 | 전체 |

## 3. 표준 오류 코드

### 인증·요청·리소스

| 코드 | 사용자 설명 | 조치 | 재시도 |
|---|---|---|---|
| `AUTH_INVALID_CREDENTIALS` | 로그인 정보를 확인할 수 없습니다. | 계정과 비밀번호를 확인합니다. | 가능 |
| `AUTH_SESSION_EXPIRED` | 로그인 시간이 만료되었습니다. | 다시 로그인합니다. | 로그인 후 가능 |
| `AUTH_ACCESS_DENIED` | 이 작업을 수행할 수 없습니다. | 로그인 상태를 확인한 뒤 다시 시도합니다. | 조건부 |
| `REQUEST_INVALID` | 요청 내용을 처리할 수 없습니다. | 입력값을 확인합니다. | 수정 후 가능 |
| `RESOURCE_NOT_FOUND` | 요청한 항목을 찾을 수 없습니다. | 목록을 새로고침하고 대상을 다시 선택합니다. | 조건부 |
| `RESOURCE_STATE_CONFLICT` | 현재 상태에서는 이 작업을 수행할 수 없습니다. | 최신 상태를 확인한 뒤 다시 시도합니다. | 조건부 |

| `CAMERA_IO_SAVE_FAILED` | 카메라 IO 설정을 저장하지 못했습니다. | 디스크 상태를 확인한 뒤 다시 시도합니다. | 조건부 |
| `CAMERA_IO_SYNC_FAILED` | 카메라 IO 설정과 DB를 동기화하지 못했습니다. | 자동 복원 결과를 확인하고 다시 시도합니다. | 조건부 |

| 코드 | 사용자 설명 | 조치 | 재시도 |
|---|---|---|---|
| `PROCESSING_ALREADY_ACTIVE` | 이미 대기 또는 처리 중인 작업이 있습니다. | 현재 작업을 확인하거나 취소한 뒤 다시 시도합니다. | 조건부 |
| `PROCESSING_ENQUEUE_FAILED` | 처리 작업을 대기열에 등록하지 못했습니다. | 잠시 후 다시 시도합니다. | 가능 |

| `PROCESSING_CHECKPOINT_FAILED` | 처리 복구 정보를 저장하거나 불러오지 못했습니다. | 저장 공간을 확인한 뒤 처음부터 다시 처리합니다. | 조건부 |
| `PROCESSING_INTERRUPTED` | 시스템 재시작 또는 연결 중단으로 처리가 멈췄습니다. | 워커 상태를 확인한 뒤 다시 처리합니다. | 가능 |

| `GPU_DEVICE_UNAVAILABLE` | GPU 처리 장치를 사용할 수 없습니다. | GPU 워커와 장치 연결 상태를 확인합니다. | 조건부 |

사용자 화면에는 처리 스크립트 이름, 종료 코드, 실행 명령, 표준 출력과 표준
오류 원문을 표시하지 않습니다. 단계명처럼 조치에 필요한 안전한 정보만 별도
필드로 제공합니다.

## 4. 분류 우선순위

한 예외가 여러 분류에 걸칠 때 다음 순서를 적용합니다.

1. 사용자가 취소한 작업은 오류가 아니라 `cancelled` 상태로 처리합니다.
2. 입력 검증 실패는 시스템 장애보다 먼저 분류합니다.
3. 파일, 저장소, DB, 대기열, GPU처럼 원인을 확인할 수 있으면 해당 코드를
   사용합니다.
4. 처리 엔진의 하위 오류를 확정할 수 없을 때만 `PROCESSING_STEP_FAILED`를
   사용합니다.
5. 어떤 분류에도 안전하게 매핑할 수 없을 때만 `INTERNAL_ERROR`를 사용합니다.

문자열 일부를 단순 검색해 분류하는 방식은 임시 호환 계층에서만 허용합니다.
새 코드는 오류를 발생시키는 위치에서 표준 코드를 명시해야 합니다.

## 5. 화면에 표시하지 않는 정보

다음 정보는 서버 로그와 오류 묶음에만 남기고 API·WebSocket·처리 상태 파일의
사용자 메시지에는 포함하지 않습니다.

- 호스트와 컨테이너의 실제 파일 경로
- 스택 트레이스와 소스 파일·줄 번호
- 외부 프로그램의 원문 출력
- SQL 문장, DB 연결 문자열, 내부 테이블 정보
- 토큰, 비밀번호, 환경변수 값
- 호스트명, 컨테이너명, 내부 IP와 포트
- 파서와 라이브러리가 반환한 원문 예외

운영 로그에는 `reference_id`, `code`, 프로젝트·작업 ID, 내부 예외와 스택을
함께 기록합니다. 사용자에게는 동일한 `reference_id`만 제공합니다.

## 6. 화면 표시 규칙

- 제목: 오류 코드의 사용자용 짧은 이름
- 본문: `message`
- 다음 행동: `action`
- 하단: `오류 참조번호: <reference_id>`와 복사 버튼
- 재시도 가능 오류만 재시도 버튼 표시
- 상세 기술 문자열을 펼치는 UI는 제공하지 않음
- 로그인 만료는 오류 화면 대신 로그인 화면으로 이동
- 여러 항목의 부분 실패는 항목별 코드와 참조번호를 제공하고 원문 예외는 숨김

## 7. 현재 코드 전환 순서

| 순서 | 현재 영역 | 전환 내용 |
|---:|---|---|
| 1 | 공통 API·프론트 클라이언트 | 표준 오류 응답, 참조번호, 안전한 기본 문구 도입 |
| 2 | 처리 워커·상태 파일·WebSocket | `error_code`, `error_reference`, 사용자 메시지 분리 |
| 3 | 업로드·EO·카메라 IO | 파서 원문 제거, 입력 오류 코드 적용 |
| 4 | 내보내기·클립 | 동기 실행을 비동기 작업으로 옮기며 코드 적용 |
| 5 | 프로젝트·그룹·파일·인증 | 남은 문자열 `HTTPException`을 표준 오류로 전환 |
