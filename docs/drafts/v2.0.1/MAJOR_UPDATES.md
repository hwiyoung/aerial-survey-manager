# v1.0.0 대비 v2.0.1 주요 업데이트

> 상태: 작성 중인 초안. 릴리즈 후보 확정 시 변경 범위와 검증 결과를
> 다시 산정합니다.

이 문서는 Aerial Survey Manager `v1.0.0`에서 `v2.0.1`로
업데이트할 때 사용자가 체감하는 기능 변화와 운영자가 확인해야 할 사항을
요약한 문서입니다.

- 비교 기준: Git 태그 `v1.0.0` → `v2.0.1`
- 릴리즈 버전: `2.0.1`
- 반영 범위: 릴리즈 후보 확정 시 산정
- 용도: 기능 변경 확인 및 업데이트 후 검수
- 설치 명령: [간단 업데이트 가이드](UPGRADE_QUICKSTART.md)
- 백업·롤백 포함 절차: [상세 업데이트 가이드](UPGRADE_GUIDE.md)

> **중요:** 아래 2번의 원점·좌표계 변경은 처리가 완전히 끝난 결과를
> 사후 변환하는 기능이 아닙니다. 작업이 대기 또는 처리 중이고 최종 결과
> 저장 단계에 들어가기 전에 변경을 예약하면, 최종 COG 생성 및 좌표 변환
> 전에 적용되는 복구 기능입니다.

## 번호별 상세 설명

1. **EO 포인트 클릭 미리보기 개선**
   - 이미지 DB 크기 또는 실제 로드 크기로 미리보기 프레임을 계산합니다.
   - `object-contain` 방식으로 가로·세로 이미지를 자르지 않고 표시합니다.
   - 파일명, EO 위치·고도, Omega·Phi·Kappa를 구분된 카드로 보여줍니다.
   - 미리보기가 없으면 클릭 시 썸네일 생성을 요청하고 진행 상태를 표시합니다.

2. **원점·입력 좌표계 변경 후 처리**
   - TM 서부 `EPSG:5185`, 중부 `EPSG:5186`, 동부 `EPSG:5187`,
     동해 `EPSG:5188`, UTM-K `EPSG:5179`, WGS84 `EPSG:4326`을 지원합니다.
   - 잘못 선택한 EO 원본 좌표계를 대기·처리 중에 다시 선택할 수 있습니다.
   - 변경 예약 즉시 지도 EO 포인트를 새 좌표계 기준으로 다시 계산합니다.
   - 최종 COG/warp 직전에 예약된 좌표계 태그를 적용하고 상태를 기록합니다.
   - 최종 결과 저장 전에는 예약을 바꾸거나 취소할 수 있지만, 최종 저장 단계에
     들어간 뒤에는 변경할 수 없습니다.

3. **EO Import 및 내용 표출 개선**
   - 배포 PC의 허용된 경로에서 EO 파일을 선택하고 추가로 불러올 수 있습니다.
   - 선택한 EO 파일명과 경로, 원본 내용을 읽어 표 형태로 표시합니다.
   - 이미지명과 EO 행을 대조하여 매칭·미매칭·중복·제외 상태를 보여줍니다.
   - 열 번호 매핑, 구분자, 헤더, CRS를 조정한 결과가 미리보기에 반영됩니다.
   - 서로 다른 CRS가 섞였거나 사용할 EO 행이 없으면 잘못된 처리를 막습니다.

4. **EO 기반 정합 및 처리 옵션**
   - EO-only 정합 모드와 미정합 카메라 재정합 흐름을 추가했습니다.
   - 작업별 처리 모드, GSD, 출력 좌표계, EO 정합, 체크포인트 옵션을
     DB에 보존합니다.

5. **서버 경로 기반 이미지 불러오기**
   - 브라우저로 대용량 파일을 다시 전송하지 않고, 배포 PC에 이미 저장된
     이미지 폴더 또는 여러 파일을 선택할 수 있습니다.
   - 허용된 저장소 경로 안에서만 탐색하고 이미지 수를 먼저 확인합니다.

6. **업로드 직후 처리 예약**
   - 프로젝트 생성 마지막 단계에서 자동 처리를 선택하면 업로드가 끝난 뒤
     처리 작업을 바로 대기열에 등록합니다.

7. **로컬 스토리지 기본 지원**
   - 단일 서버 설치는 로컬 디스크만으로 운영할 수 있습니다.
   - MinIO를 사용하던 기존 설치는 MinIO 프로필과 기존 볼륨·경로를 그대로
     유지하여 업데이트할 수 있습니다.

8. **데이터·공유 경로 분리**
   - 프로젝트 처리 데이터와 최종 정사영상, 오프라인 타일을 각각 다른
     경로로 지정할 수 있습니다.
   - 공유해야 하는 `orthomosaic`과 `tiles`는 상위 공용 경로에 두고 여러
     스택에서 같은 호스트 경로를 마운트할 수 있습니다.

9. **처리 복구와 중복 실행 방지**
   - 워커 재시작 또는 일시적인 GPU 문제 뒤에 작업을 복구할 수 있도록
     redelivery와 체크포인트 재시작 절차를 개선했습니다.
   - 하나의 프로젝트에 활성 작업이 중복 생성되지 않도록 DB 제약을 둡니다.

10. **처리 단계 및 진행 상태 통합**
    - API, 워커, UI가 같은 처리 단계 정의를 사용하도록 정리했습니다.
    - 처리 화면에서 현재 단계와 진행 메시지를 더 일관되게 확인할 수 있습니다.

11. **GPU 처리 워커 운영 개선**
    - Metashape 처리 경로를 전용 엔진 워커와 `gpu-engine` 큐로 통일했습니다.
    - GPU 상태 진단과 자동 복구를 위한 watchdog 및 점검 스크립트를 제공합니다.

12. **썸네일 작업 분리**
    - 대용량 썸네일 생성이 일반 Celery 작업을 막지 않도록 전용 큐와 워커를
      사용합니다.
    - 기존 데이터에 썸네일이 없더라도 EO 포인트에서 필요할 때 생성할 수
      있습니다.

13. **정사영상 생성·내보내기 관리**
    - 사람이 식별하기 쉬운 정사영상 파일명을 사용하고 COG 중복 생성을
      방지합니다.
    - 다른 프로젝트와 파일명이 겹치면 `(1)`, `(2)` 번호를 자동 부여하고,
      RC.1 UUID 폴더 결과는 전용 도구로 파일과 DB 경로를 함께 변환합니다.
    - 내보내기 취소와 선택적 COG 삭제, 완료 산출물 보존 흐름을 제공합니다.

14. **외부 COG 등록**
    - 다른 도구나 외부 스택에서 만든 COG를 프로젝트 결과로 등록하여
      대시보드에서 관리할 수 있습니다.

15. **도엽 클립·머지**
    - 1:5,000 및 1:1,000 도엽 기준으로 정사영상을 자르거나 합칠 수 있습니다.

16. **지도 및 대시보드 UX**
    - 베이스맵 전환, 자유 이동, 원래 범위 복귀, 줌 확대, 레이어 순서 유지 등
      실제 검수 작업에 필요한 지도 조작을 개선했습니다.

17. **조직 공유와 접근 보안**
    - 조직 단위 공동 운영과 사용자 정의 카메라 모델 공유 범위를 정리했습니다.
    - 프로젝트 산출물의 직접 URL 노출을 줄이고 권한이 확인된 단기 URL을
      사용합니다.

18. **오프라인 배포와 운영 안정성**
    - 인터넷이 없는 배포 PC에서도 Docker 이미지를 로드하여 설치할 수 있습니다.
    - systemd, 외장 디스크 마운트 의존성, GPU watchdog을 통해 재부팅 후
      서비스 시작 순서를 관리합니다.
    - 운영하지 않는 레거시 처리 엔진과 관련 의존성을 제거했습니다.
