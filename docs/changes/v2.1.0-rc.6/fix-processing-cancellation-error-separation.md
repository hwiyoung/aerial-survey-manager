- DB 마이그레이션: `없음`
- 환경변수·설정 변경: `없음`
- 컨테이너 재빌드: `필요 - frontend, api, worker-engine`

## 업데이트 내용

정상 취소는 오류가 아니라 `cancelled` 상태로 저장하고 회색 안내로 표시합니다.
취소 상태를 먼저 확정한 뒤 워커 종료 신호를 보내 종료 예외가
`PROCESSING_STEP_FAILED`로 덮어쓰지 않도록 했습니다. 취소 상태 저장 자체가
실패한 경우에만 `PROCESSING_CANCEL_FAILED`를 반환합니다.

## 변경 전

실행 중 작업을 종료하는 순간 워커 예외가 먼저 기록되면 사용자가 취소한
프로젝트가 처리 실패로 보일 가능성이 있었습니다. 취소 상태에 대한 별도 안내도
없어 상태 의미가 분명하지 않았습니다.

## 변경 후

정상 취소에는 오류 코드·조치·참조번호를 표시하지 않고 다시 시작 방법만
안내합니다. 실제 취소 실패와 실제 처리 실패만 빨간 오류 카드와 참조번호를
사용합니다.

## 검증 내용

- 대기·실행 상태 취소에서 DB 저장이 워커 종료보다 먼저 실행되는지 검증
- 워커 제어 채널 예외 후에도 `cancelled` 상태가 유지되는지 검증
- DB 저장 실패만 `PROCESSING_CANCEL_FAILED`로 분류되는지 검증
- 프론트 lint·build와 백엔드 전체 테스트 통과
