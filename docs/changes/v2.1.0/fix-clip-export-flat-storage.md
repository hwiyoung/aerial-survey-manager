# 클립 정사영상 저장 경로와 파일명 정리

- 대상 버전: `v2.1.0`
- 분류: `버그 수정`
- 영역: `정사영상 내보내기 | 저장소`
- 사용자 영향: `있음`
- DB 마이그레이션: `없음`
- 환경변수·설정 변경: `없음`
- 컨테이너 재빌드: `필요 - frontend, api, celery-worker`
- 기존 데이터 영향: `신규 결과의 저장 위치와 보존 방식 변경`

## 업데이트 내용

클립 결과를 작업 UUID 하위 폴더가 아니라 일반 정사영상과 같은
`orthomosaic/` 루트에 저장합니다. 단일 프로젝트의 기본 파일명은
`{권역명}_{프로젝트명}_ortho_clip.tif`이며, 중복 시 `(1)`, `(2)`를
자동으로 붙여 기존 파일을 보호합니다.

## 변경 전

완료된 결과가 `orthomosaic/clip-jobs/{job_uuid}/`에 남아 운영자가
프로젝트명으로 찾기 어려웠습니다. 화면의 기본 이름이 권역명 없이
전달되면 백엔드 기본 규칙도 우회했습니다.

## 변경 후

작업 UUID 폴더는 처리 중 임시 공간으로만 사용하고 완료·취소·오류 후
정리합니다. 최종 결과는 `orthomosaic/` 바로 아래로 이동하며, 화면과
백엔드가 권역명을 한 번만 포함하도록 함께 검사합니다.

## 운영자 참고사항

DB 스키마와 환경변수 변경은 없습니다. 프런트, API, 일반 Celery 워커를
재빌드·교체해야 합니다. 새로 생성되는 루트 클립 결과는 기존 7일
`clip-jobs` 정리 대상이 아니므로 사용자가 최근 클립 이력에서 삭제하거나
운영자가 정리할 때까지 보관됩니다.

최근 클립 이력의 `서버 결과 삭제`는 실제 결과 파일만 제거하고 도엽번호,
파일명과 처리 상태 이력은 유지합니다. 이미 삭제되었거나 유실된 결과에 다시
삭제를 요청해도 안전하게 이력 상태를 정리합니다.

업데이트 전에 생성된 `clip-jobs` 결과는 자동으로 루트로 이동하지 않으며
기존 DB 경로를 유지합니다. 개발 PC에서 이번 검증에 사용한 완료 결과는
파일과 DB 경로를 수동으로 맞췄지만, 이 런타임 데이터 변경은 배포
패키지에 포함되지 않습니다.

## 검증 내용

- 클립 기본 이름의 권역명 포함 및 중복 접두어 방지
- 기존 파일이 있을 때 `(1)`, `(2)` 순서 선택
- 실제 클립 완료 결과의 루트 저장, DB 경로, 다운로드 파일 확인
- 긴 한글 권역·프로젝트명이 파일시스템 바이트 한도를 넘지 않는지 확인
- 최근 이력에서 서버 결과 삭제 및 관리 경로 밖 삭제 차단
- 프런트 production Docker 빌드와 실제 제공 번들 확인

## 알려진 제한

여러 프로젝트를 하나로 클립할 때는 권역이 하나로 확정되지 않으므로 기존
`bulk_export_clip` 기본 이름을 유지합니다.
