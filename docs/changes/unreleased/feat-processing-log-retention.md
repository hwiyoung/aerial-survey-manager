# 프로젝트 처리 로그 보존 정책

- 대상 버전: `v2.0.1`
- 분류: `운영 개선`
- 영역: `처리 | 로그 | 장애 분석`
- 사용자 영향: `없음`
- DB 마이그레이션: `없음`
- 환경변수·설정 변경: `선택 - 기본값 제공`
- 컨테이너 재빌드: `필요 - api, worker-engine`
- 기존 데이터 영향: `기존 processing.log는 다음 처리 시 크기 기준으로 순환`

## 업데이트 내용

Docker의 API·Worker 로그 순환 정책은 그대로 유지합니다. 프로젝트별
`processing/.logs/processing.log`와 자동 내보내기 로그에는 50MB 크기와 백업
3개의 기본 순환 정책을 적용합니다.

처리 오류가 발생하면 오류 참조번호별 `tar.gz` 진단 묶음에 최근 처리 로그,
상태 파일과 처리 manifest를 보존합니다. 묶음은 기본 30일, 프로젝트당 최근
20개, 전체 20GB 정책으로 오류 발생 시와 API 시작 시 자동 정리합니다. 이 묶음은
운영 진단용이며 사용자 오류 응답에는 경로·원문 로그를 노출하지 않습니다.
