# 사용자 안전 오류 안내 체계

- 대상 버전: `v2.0.1`
- 분류: `기능 개선`
- 영역: `API | 처리 | 프론트`
- 사용자 영향: `있음`
- DB 마이그레이션: `있음 - processing_jobs에 nullable 오류 코드·참조번호 추가`
- 환경변수·설정 변경: `없음`
- 컨테이너 재빌드: `필요 - frontend, api, worker-engine, celery-worker`
- 기존 데이터 영향: `없음`

## 업데이트 내용

오류 표시를 오류 코드, 사용자용 설명, 조치 방법, 오류 참조번호로 통일합니다.
기술 예외 원문은 운영 로그에만 보존하고 화면에는 표시하지 않습니다.

## 구현 기준

오류 유형과 표준 코드는 `docs/ERROR_CATALOG.md`에서 먼저 확정합니다. API,
처리 상태, WebSocket, 프로젝트 목록과 프론트 알림이 같은 형식을 사용하도록
단계적으로 전환합니다.

처리 작업 오류 코드와 참조번호는 DB, 상태 파일과 WebSocket에 동일하게
기록하며 프로젝트 목록과 처리 화면에서도 같은 값을 표시합니다.

React 화면 렌더링 자체가 실패한 경우에도 예외 문자열과 스택은 화면에 표시하지
않고, 사용자용 설명·조치·오류 참조번호만 제공합니다. 기술 정보는 같은 참조번호와
함께 브라우저 개발자 콘솔에 기록합니다.

## 검증 내용

- API 4xx·5xx의 표준 응답 형식
- 처리 실패 상태와 WebSocket의 동일 참조번호
- 파일 경로, 스택, 외부 프로그램 원문 비노출
- 참조번호로 서버 로그와 오류 묶음 검색
