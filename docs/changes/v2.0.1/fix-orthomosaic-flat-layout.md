# 정사영상 최종 폴더 구조 복원

- 대상 버전: `v2.0.1`
- 분류: `버그 수정`
- 영역: `처리 | 배포`
- 사용자 영향: `있음`
- DB 마이그레이션: `있음 - v2.0.0에서 생성된 UUID 폴더 결과만 운영 도구로 변환`
- 환경변수·설정 변경: `없음`
- 컨테이너 재빌드: `필요 - api, worker-engine, celery-worker`
- 기존 데이터 영향: `있음 - UUID 하위 폴더의 현재 COG와 DB 경로를 함께 변환`

## 업데이트 내용

최종 정사영상이 다시 `EXPORT_ROOT_PATH/{region}_{title}.tif` 형식으로
저장됩니다. 동일한 최종 파일명을 다른 프로젝트나 기존 파일이 사용 중이면
기존 파일을 덮어쓰지 않고 `(1)`, `(2)` 번호를 붙여 저장합니다.

## 변경 전

`v2.0.0`은 `EXPORT_ROOT_PATH/{project_uuid}/...tif` 하위 폴더를
생성했습니다. 재처리 결과는 job UUID까지 파일명에 포함했습니다.

## 변경 후

최종 폴더는 평면 구조를 유지하고, 작업별 중간 파일은 프로젝트의
`.work` 폴더에서만 분리됩니다. 같은 프로젝트를 재처리하면 완성된
새 COG가 기존 최종 파일을 원자적으로 교체합니다. 다른 프로젝트의 이름과
겹치면 `{region}_{title} (1).tif`처럼 비어 있는 첫 번호를 사용합니다.
최종 COG 발행은 워커 한 곳에서만 수행해 자동 내보내기와 최종 저장이
중복 파일을 만드는 상황도 방지합니다.

## 운영자 참고사항

업그레이드 전 DB와 `EXPORT_ROOT_PATH` 전체를 백업합니다. 수정 버전을
시작한 뒤 `./scripts/migrate-orthomosaic-layout.sh`로 dry-run을 확인하고,
자동 선택된 번호와 프로젝트 매핑이 맞고 누락·추가 파일 경고가 없을 때만
`--apply`를 실행합니다. `AUTO_EXPORT_ENABLED`는 `false`로 유지합니다.
수동 `mv`는 사용하지 않습니다.

## 검증 내용

- 평면 최종 키 생성과 파일 이동 확인
- 같은 프로젝트 재처리 시 완성 파일 교체 확인
- 다른 프로젝트 및 DB 미등록 파일에 대한 `(1)`, `(2)` 자동 번호 확인
- UUID 하위 폴더 마이그레이션의 dry-run, 자동 번호, 추가 파일 보호 확인

## 알려진 제한

마이그레이션 도구는 로컬 스토리지 배포만 지원합니다. UUID 폴더에
현재 DB가 가리키는 COG 외의 과거 결과가 있으면 자동으로 옮기지 않습니다.
